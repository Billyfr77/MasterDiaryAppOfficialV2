🏗️ MasterDiaryOS — Workflow Builder Intelligence & Power-Up Specification (Phase 2)
Authoritative, Non‑Breaking Upgrade Specification for Gemini 3 CLI
Excludes Simulation Mode (Phase 1)
This document defines the remaining enhancements required to evolve the MasterDiaryOS Workflow Builder into a cinematic, AI‑native orchestration engine.

All changes must be:

Additive only

Non‑breaking

Backward compatible

Respectful of existing architecture, naming, and data models

Isolated into new modules

Read‑only unless explicitly stated otherwise

Gemini 3 CLI must treat this as a feature expansion, not a refactor.

Each module is safe to implement independently.

1. Node Intelligence Layer
Purpose
Give every node the ability to self‑analyze, self‑describe, and self‑predict.

Requirements
Add a new non-destructive “intelligence” interface for all node types.

Must not modify existing node classes.

Must attach via composition or extension.

Capabilities
Each node must expose:

describePurpose()

listRequiredInputs()

listOptionalInputs()

detectMissingInputs()

predictExecutionOutcome()

suggestImprovements()

Output
Structured JSON + human-readable summaries.

2. Auto‑Config & Auto‑Repair Suggestions
Purpose
Provide safe, advisory-only configuration fixes.

Requirements
Must never auto‑apply changes.

Must never modify workflow data.

Must generate suggestions only.

Capabilities
Suggest default values

Suggest approvers

Suggest safety docs

Suggest diary requirements

Suggest resource allocations

Suggest milestone dependencies

3. Time/Cost/Risk Overlays (Non‑Simulation)
Purpose
Provide static overlays independent of Simulation Mode.

Requirements
Must not run simulations

Must not modify workflow

Must not conflict with Simulation Mode overlays

Capabilities

Cost estimates per node

Critical path preview

Cost accumulation preview
